# Koito JR v0.2.1

This release fixes security and reliability issues in Koito JR v0.2.0. Highlights include safer first-run credentials, narrower scrobbler-key permissions, bounded requests and artwork downloads, and fixes to ListenBrainz relay retries and large-history exports.

## Authentication changes

- New installs accept a password supplied at setup. If you omit it, run `docker compose exec koito ./app reset-password` once the service is ready. Startup logs no longer contain the initial password.
- Existing passwords and scrobbler keys carry over. Change the password explicitly if the installation still uses the old default.
- Scrobbler keys still validate and submit ListenBrainz listens. They can also read gated statistics. Account management, exports and editing require a browser session.
- Changing a password requires the current password and signs out other sessions. The reset command signs out all sessions. New sessions expire after 24 hours, or 30 days with Remember me.
- A reverse proxy must preserve the public Host header for origin checks. If it terminates HTTPS, configure it to set Secure on the session cookie. Clients reaching Koito through the same proxy share a login limit.

## Upgrade and rollback

Keep the existing SQLite data mount and back up the full data directory with Koito stopped. Keep the previous image digest. No schema migration is introduced by this release. On rollback, v0.2.0 can keep using its cached artwork, but it cannot refetch uncached artwork stored using the new Subsonic cover IDs. Keep the image cache with the backup.

The ListenBrainz request-body limit is 5 MiB. Web request bodies, including multipart uploads, are limited to 10 MiB when read. Use the local import directory for larger files. Large streaming exports remain subject to the server write timeout.

## Security limits

Listening statistics are public unless `KOITO_LOGIN_GATE=true` is enabled. API keys remain readable in SQLite and the authenticated account UI. Older databases, exports, backups and logs may still contain credentials. Treat them as sensitive and rotate credentials that may have been exposed.

Remote image URLs must resolve to public addresses. Private artwork can use an uploaded file or an explicitly configured Subsonic cover source. Subsonic startup checks and cover fetches reject redirects, so configure the final server URL.
